---
title: "區塊鏈算是哪一種資料庫？"
---

如果用常見的幾種資料庫分類來看，區塊鏈比較接近 **NoSQL**。但更精確的說法是：它是一種**分散式帳本 (distributed ledger)**，其實不完全屬於傳統資料庫的分類，跟一般資料庫的設計目標也不一樣。

### 套用常見的資料庫分類

| 分類 | 區塊鏈屬於 | 原因 |
| --- | --- | --- |
| RDBMS vs. NoSQL | 偏 NoSQL | 沒有 table、JOIN、foreign key。節點底層通常用 key-value store：Bitcoin Core 和 Geth 都用 LevelDB，Geth 新版改用 Pebble |
| OLTP vs. OLAP | 偏 OLTP | 核心功能是記錄交易，但吞吐量遠低於一般 OLTP 資料庫。鏈上資料分析通常要先匯出到 BigQuery、ClickHouse 這類 OLAP 系統 |
| 伺服器型 vs. 檔案型 | 都不是 | 它是點對點網路，沒有中心的 server，每個 full node 都存一份完整資料 |
| ACID | 部分符合 | 單筆交易有 atomicity，失敗會整筆 revert。durability 則要看共識機制：PoW 鏈的區塊有可能被重組 (reorg)，所以只能做到機率上的最終確定 |
| CAP | 看共識機制 | Bitcoin 的 PoW 偏 **AP**：網路分區時仍會繼續出塊，之後以最長鏈收斂，屬於最終一致性。Tendermint 這類 BFT 共識偏 **CP**：超過 1/3 的驗證者離線時鏈會停住，但已確認的區塊不會被推翻 |

### 跟一般資料庫最根本的差別

一般資料庫假設**所有參與者都是可信任的**，例如同一家公司的 server，所以重點放在效能和一致性。

區塊鏈假設**參與者之間互不信任**，所以要用共識機制和密碼學 (hash chain、數位簽章)，換來以下特性：

- **Append-only、不可竄改**：只能新增資料，不能修改或刪除舊資料。改動任何一個區塊，後面所有區塊的 hash 都會對不上。
- **去中心化**：沒有單一管理者，誰都不能自己決定改資料。
- **可驗證**：任何人都可以從創世區塊開始，自己重新驗證所有交易。

代價是速度慢、儲存成本高、沒有彈性的查詢能力。所以實務上，dApp 的後端常常會另外搭一個 indexer（例如 The Graph，或自己寫一個把鏈上事件同步進 PostgreSQL 的服務），用一般的資料庫來處理查詢。

也就是說，區塊鏈的定位比較像一個**大家共同維護、不可竄改的交易紀錄**，而不是拿來取代資料庫的通用儲存系統。
